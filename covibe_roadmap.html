CoVibe product roadmap แบ่งเป็น 4 phases และ tasks ย่อย

Phase 0 Feasibility Spike — พิสูจน์ว่าใช้ได้จริง 3–5 วัน

ก่อนลงทุน Sprint จริง ต้องรู้ก่อนว่า YouTube IFrame + WebSocket sync ทำงานได้จริงบนมือถือ 2 เครื่องหรือไม่ และระบุข้อจำกัดของแพลตฟอร์ม

Sprint 0 Technical Spike 3–5 วัน
Prototype YouTube IFrame Player บน 2 clients พร้อมกัน
WebSocket room ขั้นต่ำ: สร้างห้อง / join / broadcast event
Play / Pause / Seek sync เบื้องต้น
วัด drift จริงระหว่าง 2 เครื่อง
ทดสอบบน iOS Safari + Android Chrome
ระบุข้อจำกัด autoplay / background playback / wake lock
Exit criteria
มือถือ 2 เครื่องเล่นเพลงเดียวกัน drift เฉลี่ย < 500ms
Join ด้วย room link ได้
มี document สรุปข้อจำกัดของแต่ละแพลตฟอร์ม
Phase 1 MVP Core — สร้างและ join ห้องได้ 2 สัปดาห์

วางรากฐาน backend + frontend ให้ Rider สร้างห้อง และ Passenger join ผ่าน QR ได้ในสภาพแวดล้อมใกล้เคียง production

Sprint 1A Project Setup + Room Creation 1 สัปดาห์
ตั้งโปรเจกต์ React + Vite (PWA manifest, service worker shell)
Backend Node.js + TypeScript + Socket.IO พร้อม Redis room state
Rider: สร้างห้อง → รับ roomId → แสดง QR code
QR generator + share link
Passenger: สแกน QR → ใส่ชื่อ → join ห้อง
Participant presence (connected / disconnected)
Thai UI ขั้นพื้นฐาน, dark mode, mobile-first layout
Exit criteria
Rider เปิดห้องและ Passenger join ได้บน production URL จริง
Sprint 1B Queue + Playback Sync 1 สัปดาห์
YouTube link parser + YouTube IFrame API integration
Queue เพลง: add / remove / reorder
Current track state บน server (trackId, positionMs, serverStartedAt)
Play / Pause / Skip / Seek ซิงค์ผ่าน WebSocket
Auto-next เมื่อเพลงจบ
Volume control แยกแต่ละ device
Exit criteria
เล่นเพลงต่อคิว 5 เพลงขึ้นไปโดยไม่ต้อง refresh
Phase 2 Hardening + Rider UX — พร้อม Beta 2 สัปดาห์

เพิ่มความเสถียร drift correction, reconnect และทำ Rider UX ให้ขับได้จริง ก่อนส่ง Beta users ใช้

Sprint 2A Sync Hardening 1 สัปดาห์
Drift correction algorithm (<250ms ปล่อย / 250-800ms ปรับ rate / >800ms seek)
Latency ping ทุก 1-3 วินาที + clock sync กับ server
Reconnect อัตโนมัติหลังเน็ตหลุด + resync position
Buffer state handling + แจ้งผู้ใช้เมื่อ buffering
Host handoff fallback เมื่อ Rider ออกจากห้อง
Drift metric logging สำหรับ debug
Exit criteria
เน็ตหลุดแล้วกลับมา drift < 500ms ภายใน 5 วินาที
Sprint 2B Rider Mode + Beta Polish 1 สัปดาห์
Rider dashboard ปุ่มใหญ่ (Play/Pause/Skip) อ่านได้กลางแดด
OLED saver / black screen mode พร้อม control ขั้นต่ำ
Passenger remote: ค้นหา YouTube + เพิ่มเพลงเข้าคิว
Trip summary หน้าสรุปหลังจบทริป
Analytics events ขั้นพื้นฐาน (room created, joined, played, drift avg)
Error tracking integration (Sentry หรือเทียบเท่า)
Exit criteria
Beta users ใช้ได้โดยไม่ต้องมี developer คอยประกบ
Phase 3 Private Beta — ทดสอบกับผู้ใช้จริง 2–3 สัปดาห์

ปล่อยให้กลุ่ม 20–50 คู่ขี่ทดลองจริง เก็บ feedback, bugs และ retention data เพื่อตัดสินใจ roadmap ถัดไป

Sprint 3A Beta Onboarding + Distribution 1 สัปดาห์
Beta onboarding flow อธิบาย autoplay tap + วิธีใช้
In-app feedback form + rating หลังจบทริป
เชิญ 20–50 คู่แรก ผ่านกลุ่ม Facebook / เพื่อน
ทำ demo video สำหรับ TikTok/Reels + ช่องทาง Beta
QR ติดร้านหมวก/อุปกรณ์มอเตอร์ไซค์ (ถ้าได้)
Sprint 3B Monitoring + Learning 1–2 สัปดาห์
Usage dashboard: trips, activation rate, listening duration
Retention tracking: repeat trip ภายใน 7 วัน
รวบรวม top 5 bugs จาก error log + feedback
วิเคราะห์ว่า persona ไหน retain ดีที่สุด (คู่รัก / BigBike / TWS)
Quick-fix iteration จาก feedback
Exit criteria
อย่างน้อย 20 ทริปที่ฟังต่อเนื่องเกิน 15 นาที (North Star)
รู้ top 5 bugs และ persona ที่ retain ดีที่สุด
Phase ถัดไป (ไม่ใช่ MVP) Post-Beta Expansion — ต่อยอดหลังพิสูจน์ demand TBD

ฟีเจอร์เหล่านี้ยังไม่ทำใน MVP เพราะมีความเสี่ยงด้านแพลตฟอร์มสูง รอพิสูจน์ demand จาก Beta ก่อน

เฟสถัดไป Backlog ที่รอ demand จาก Beta
Hotspot / Local WebSocket mode (ไม่พึ่ง cloud)
Intercom voice chat
Convoy GPS tracking
Voice command
Payment / subscription model
Offline YouTube download (ถ้า legal)
Native App (iOS/Android) สำหรับ background playback ที่ดีขึ้น
Spotify / Apple Music integration
